# STM32F407 + RT-Thread + LVGL 二次开发与学习指南

配套的分层结构、线程通信、传感器采集、姿态融合和 UI 导航图见
[《软件架构与逻辑框图》](软件架构与逻辑框图.md)。

## 1. 这个工程已经具备什么

- STM32F407ZGT6，外部 8 MHz 晶振，系统主频 168 MHz。
- RT-Thread 5.2.2 内核。
- LVGL 9.5.0，240 × 240、RGB565、24 行局部刷新缓冲。
- ST7789V3 屏幕，FSMC Bank 3、8 位数据总线。
- PC0/PC1/PC4/PC5 四个方向键控制 LVGL：上/下选择，右键确认，左键返回。
- USART1 固定为 115200、8N1，通过板载 ST-LINK 虚拟串口查看启动 Logo 和日志。
- 集成 RT-Thread 官方 FinSH/MSH，可通过串口输入系统与板级诊断命令。
- 主界面右上角显示“夙夜凌风”；工程内置的精简字库只包含这四个汉字。
- 三个板载传感器、W25Q Flash、SD 插卡和 RW007 硬件状态均使用真实数据。
- AHT21 原始值和一维 Kalman 结果可独立查看；ICM20608 提供四元数相对姿态。

## 2. 目录职责

```text
Applications/
├─ app_init.c                 极薄的 RT-Thread 应用启动钩子
├─ runtime/
│  └─ app_tasks.*             所有线程注册、启动参数、快照和线程间请求
├─ serial_console_ui.*        窄终端兼容的 ASCII Logo 和快捷帮助
├─ shell_commands.c           自定义 MSH 板级诊断命令
├─ lvgl_port/                 LVGL 与硬件之间的适配层
│  ├─ lv_port_disp.*          显示注册、刷新回调、局部缓冲
│  └─ lv_port_indev.*         四方向键与 LVGL 输入组
└─ lvgl_ui/                   只放界面，不直接操作 STM32 寄存器
   ├─ ui_boot_screen.*        RT-Thread 与“夙夜凌风”非阻塞开机动画
   ├─ ui_navigation.*         所有页面切换和返回逻辑
   ├─ ui_main_menu.*          2 × 3 六功能主菜单
   ├─ ui_feature_pages.*      传感器、滤波、姿态、存储、网络、系统页
   └─ ui_font_chinese_14.c    “夙夜凌风”四字子集字体

BSP/
├─ services/
│  └─ board_service.*         驱动/算法编排和快慢速采样策略，不创建线程
├─ algorithms/
│  └─ sensor_fusion.*         可移植的一维 Kalman、Mahony 四元数与归零算法
├─ drivers/
│  ├─ bus/                    软件 I2C、SPI2 总线电气层
│  ├─ sensors/                AHT21、AP3216C、ICM20608 独立驱动
│  ├─ storage/                W25Q JEDEC 探测和 SD 插卡检测
│  └─ wireless/               RW007 复位与 INT/BUSY 管脚驱动
├─ lcd/
│  └─ st7789_fsmc.*           屏幕复位、背光、FSMC、ST7789 命令
├─ rt_hw_console.c            USART1 RT-Thread 控制台
└─ rtthread_startup.c         RT-Thread 内核启动入口

Core/                         STM32CubeMX 生成代码，时钟继续由 .ioc 管理
Middlewares/Third_Party/
├─ RT-Thread/                 操作系统内核
└─ LVGL/                      LVGL 9.5.0 与 lv_conf.h

tools/
├─ build.ps1                  一键构建
└─ flash.ps1                  一键 ST-LINK 烧录、校验和复位
```

最重要的边界是：页面代码只调用 LVGL 和 `app_tasks` 快照/请求接口，不直接访问 HAL/寄存器；任务层负责通信；服务层负责编排；驱动层不认识线程和页面。以后换屏、传感器或开发板时，UI 通常可以原样保留。

### 2.1 当前六个功能页

以下设备与总线来自 RT-Thread v5.2.2 官方 `stm32f407-rt-spark` BSP 和开发板原理图。ICM20608 约 50 Hz 更新；AHT21 的 85 ms 转换使用非阻塞状态机；LVGL 每 500 ms 读取一次快照，不会因测量等待阻塞界面：

| 页面 | 当前功能 | 状态/边界 |
|---|---|---|
| Sensors | AHT21 温湿度、AP3216C 光照/接近、ICM20608 加速度/陀螺仪 | 三个器件均已实机响应；使用官方软件包的寄存器与换算方式 |
| Temp/RH | 温湿度原始值与独立一维 Kalman 结果 | 过程噪声 Q：0.02/0.05；测量噪声 R：0.30/0.80，可在 `BSP/services/board_service.c` 调参 |
| Attitude | 相对 roll/pitch/yaw、四元数、静止状态、芯片温度 | 开机连续静止 300 帧（约 6 秒）校准；在线学习三轴温漂系数；RIGHT 可重新归零 |
| Storage | W25Q JEDEC ID、容量和 SD 插卡检测 | 实物为 W25Q64 8 MiB；DFS/FAL/FATFS 尚未加入 |
| Network | RW007 复位、RST、INT/BUSY、SPI2、READY 状态 | 完整扫描/连接/IP 仍需官方 SPI/PIN/WLAN/lwIP 组件 |
| System | 版本、168 MHz、uptime、线程数、堆内存 | 使用 RT-Thread 内核真实数据并定时刷新 |

原理图将 Flash 标为 W25Q128，但实机读取 JEDEC `EF 40 17`，对应 W25Q64（8 MiB）。软件按 JEDEC 容量字节识别，不把原理图型号硬编码成实物型号。

### 2.2 板载服务和移植接口

`Applications/runtime/app_tasks.c` 是所有任务和通信的总入口：

- `app_tasks_start()`：注册并启动 `board`、`lvgl`、`tshell`。
- `app_tasks_get_board_snapshot()`：原子复制最近数据，供 GUI 和 MSH 使用。
- `app_tasks_request_board_refresh()`：请求板载线程尽快重新采样。
- `app_tasks_request_rw007_reset()`：异步请求 RW007 按官方时序启动。
- `app_tasks_request_attitude_zero()`：异步请求把当前方向定义为正方向。

`BSP/services/board_service.c` 不创建线程，只把各个驱动和算法按 20 ms/500 ms
周期组合起来。具体寄存器已经分别放入 `BSP/drivers/`；Kalman、Mahony 和四元数
只放在 `BSP/algorithms/`。学习时建议先读 `app_tasks.c` 看全局数据流，再沿着
`board_service.c` 进入某个独立驱动。

RW007 默认保持 `RST=low`，不会在系统启动时自动上电运行。实测该模块与 LCD 共用
3.3 V 电源时，开机自动释放复位会使屏幕明显频闪。需要联网时在 Network 页面执行
RESET；若模块运行后仍造成频闪，应先改善 3.3 V 供电和模块附近去耦，而不是修改
LVGL 刷新率。
以后接入 RT-Thread Sensor、SFUD/FAL 或 WLAN 框架时，优先保持 `board_service_snapshot_t` 和 `app_tasks_*` 公共接口不变，只替换驱动/服务内部实现。这样页面、按键和串口命令可以继续复用。

### 2.3 姿态算法和减少零漂

姿态计算放在 `BSP/algorithms/sensor_fusion.c`，不依赖 HAL、RT-Thread 或 LVGL。处理链如下：

1. ICM20608 配置为 ±2 g、±250 dps、约 50 Hz，并开启约 41/44.8 Hz 的芯片数字低通。
2. 开机要求开发板连续静止约 6 秒，平均 300 帧得到三轴陀螺零偏和校准温度；移动会重新计数。
3. 用加速度重力方向初始化 roll/pitch，开机 yaw 定义为 0，并保存整个开机四元数作为正方向。
4. Mahony 六轴算法用四元数积分角速度，并用重力误差长期校正 roll/pitch。
5. 当加速度接近 1 g、角速度很小时，连续静止检测执行零速偏置更新（ZUPT），跟踪升温造成的零偏变化。
6. 温度相对上一个学习点变化达到 0.5°C 时，估算并低通更新三轴 `dps/°C` 系数；系数限制为 ±0.20 dps/°C，运动时也能前馈修正温漂。
7. 相对四元数转成欧拉角后，三个显示角分别通过一维 Kalman，降低界面数字跳动。

ICM20608 是六轴器件，没有磁力计。重力只能观测 roll 和 pitch，不能观测绕重力方向的 yaw。因此 yaw 是相对开机方向，运动中的长期漂移无法仅靠软件彻底消除。进一步降低漂移时，按优先级考虑：

- 上电和按下 SET ZERO 时保持开发板静止、远离振动；预热数分钟后可再次归零。
- 使用 `attitude_status` 查看补偿后的角速度、芯片温度、三轴 bias 和温漂系数；首次从冷机升温时应保持静止，让模型取得至少两个温度学习点。
- 根据实际机械振动调整 DLPF 和 Mahony 增益；不要盲目把 Kalman R 调得很大，否则只是显示变慢。
- 对绝对航向有要求时增加磁力计或外部航向参考，再升级为九轴融合；六轴 yaw 不存在可用的绝对观测量。

## 3. 第一次构建和烧录

在项目根目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1
powershell -ExecutionPolicy Bypass -File .\tools\flash.ps1
```

也可以打开 STM32CubeProgrammer 图形界面：

1. 连接方式选 `ST-LINK`，接口选 `SWD`。
2. 点击 `Connect`。
3. 在 Erasing & Programming 页面选择 `build/codex-gcc/STM32F407_RTT.elf` 或 `.hex`。
4. 勾选校验与烧录后运行，最后按开发板复位键。

烧录成功后，在设备管理器的“端口 (COM 和 LPT)”中找到 ST-LINK Virtual COM Port。串口终端设为：

```text
波特率：115200
数据位：8
校验位：None
停止位：1
流控：None
```

复位后应依次看到 ASCII Logo、RT-Thread/LVGL 版本、主频，以及 `[1/4]` 到 `[4/4]` 的启动过程。按一次回车会出现用户指定的英文 `suye>` 系统提示符；LCD 主界面的“夙夜凌风”保持不变。

### 3.1 串口命令行怎么使用

串口工具须允许发送字符，行末选择 CR 或 CRLF。先输入 `help` 查看当前固件实际注册的命令：

| 命令 | 用途 |
|---|---|
| `help` | 查看全部命令，这是学习 MSH 的入口 |
| `ps` | 查看线程、优先级、状态和剩余栈空间 |
| `free` | 查看 RT-Thread 堆内存使用情况 |
| `version` | 查看 RT-Thread 版本 |
| `list` | 查看线程、信号量、互斥量等内核对象 |
| `logo` | 重新输出紧凑版 RT-Spark Logo 和快捷帮助 |
| `ui_status` | 查看 LCD ID、初始化、背光和按键映射 |
| `key_status` | 查看四个物理按键的实时 GPIO 状态和功能映射 |
| `ui_page system` | 不触碰按键也能诊断页面切换；还支持 environment、attitude 等页面名 |
| `sensor_status` | 输出 AHT21、AP3216C、ICM20608 最近一次真实采样 |
| `environment_status` | 对比 AHT21 原始值、Kalman 值和当前 Q/R 参数 |
| `attitude_status` | 查看角度、四元数、校准进度、ZUPT、零偏和 IMU 温度 |
| `attitude_zero` | 异步请求将当前方向设为新的 0 度正方向 |
| `storage_status` | 输出 W25Q JEDEC、容量和 PF3 SD 插卡状态 |
| `network_status` | 输出 RW007 READY、RST、INT/BUSY 和复位次数 |
| `network_reset` | 请求后台线程按官方时序复位 RW007 |
| `backlight on` / `backlight off` | 控制原理图 PF9 背光引脚 |
| `lcd_test red` | 用纯色检查 LCD 数据总线和颜色；也支持 green/blue/white/black |
| `lcd_test ui` | 纯色测试后请求 GUI 线程重新绘制菜单 |
| `reboot` | 软件复位 MCU |

`lcd_test` 直接访问 LCD 总线，但恢复 UI 的 LVGL 调用由 GUI 线程执行，避免在 shell 线程中跨线程操作 LVGL。二次开发新增命令时，参考 `shell_commands.c` 的 `MSH_CMD_EXPORT_ALIAS` 写法即可。

## 4. 用 STM32CubeMX 改时钟或外设

1. 打开根目录的 `STM32F407_RTT.ioc`。
2. 在 Clock Configuration 修改时钟；当前目标为 HSE 8 MHz、SYSCLK/HCLK 168 MHz。
3. 在 Project Manager 中保持 Toolchain/IDE 为 CMake。
4. Generate Code 后检查 `CMakeLists.txt`，不要丢失 RT-Thread、LVGL、`Applications` 和 `BSP` 的手工条目。
5. 重新运行 `tools/build.ps1`。

建议把所有自写硬件代码放在 `BSP`，所有业务和 UI 放在 `Applications`。这样 CubeMX 重新生成代码时冲突最少。

## 5. 如何手写第二个 LVGL 页面

推荐每个页面一对 `.c/.h`，例如 `ui_sensor_page.c/.h`。页面头文件只公开创建函数：

```c
lv_obj_t *ui_sensor_page_create(void);
```

创建独立屏幕后，不要在控件事件回调中直接销毁当前屏幕。先提交页面请求：

```c
ui_navigation_request_open(UI_FEATURE_SENSORS);
```

按钮业务事件放在页面文件中；真正读取传感器、文件系统或网络的代码放在 `BSP/drivers/`，调用编排放在 `BSP/services/board_service.c`。不要在 LVGL 事件回调里长时间等待，耗时工作应通过 `app_tasks_*` 请求交给 board 线程，再由快照把结果安全地交给 GUI 线程显示。

现有页面切换统一经过 `ui_navigation.c`，请求在下一次 GUI 循环处理。新页面应先创建独立 screen，把可操作控件加入同一个 `lv_group_t`。当前使用 `lv_screen_load()` 后删除旧屏幕，不使用动画切屏：LVGL 的 `prev_scr` 动画状态会暂时屏蔽输入，本板应优先保证四键操作稳定。不要让传感器线程直接修改 LVGL 控件；应通过消息、事件或快照把数据交给 GUI 线程。

开机画面位于 `ui_boot_screen.c`。GUI 线程按 RT-Thread tick 更新进度条，到期后由导航模块直接加载主菜单。启动期间 RT-Thread 仍会正常调度，不能用 `HAL_Delay(2000)` 或忙等待替代。

## 6. 图形化设计 UI

本工程采用 LVGL 9.5，优先建议使用同版本的 **LVGL Pro Editor**。它提供实时像素级预览，并能把界面导出为普通 C 代码；导出的 C 代码可以像手写页面一样编进固件。

推荐工作流：

1. 在编辑器中创建 240 × 240 项目，色深选 RGB565，LVGL 版本选 9.5。
2. 在电脑上完成页面、组件、字体和图片设计并预览。
3. 导出 C 代码到 `Applications/lvgl_ui/generated/`；不要把生成文件和手写业务事件混在同一文件。
4. 在 `CMakeLists.txt` 中把 `generated/*.c` 加入目标，并把目录加入 include path。
5. 在 `ui_main_menu_create()` 或新页面入口调用编辑器生成的初始化函数。
6. 业务逻辑放在 `Applications/lvgl_ui/custom/`，通过事件回调连接生成控件。重新导出 UI 时只替换 `generated`，不会覆盖业务代码。

如果使用 SquareLine Studio，也遵循同样的 `generated/custom` 分离方式，但必须确认它导出的代码明确支持 LVGL 9.5；不同 LVGL 大版本的 API 不应混用。

## 7. 以后移植时改哪里

### 只换 LCD 控制器

- 重写 `BSP/lcd/st7789_fsmc.*`，保持 `set_window/write_pixels` 这类接口。
- 如果分辨率或颜色格式变化，再改 `lv_port_disp.c`。
- `lvgl_ui` 无需修改，除非屏幕尺寸变化需要重新布局。

### 换 STM32 开发板

- 用新板的 CubeMX 工程替换 `Core`、启动文件、链接脚本和 HAL 配置。
- 重做 `BSP` 的 LCD 与串口连接。
- 修改 `lv_port_indev.c` 的按键或触摸输入。
- 修改 `BSP/drivers/` 中对应总线/器件驱动，必要时调整 `board_service.c` 编排，并保持快照接口。
- 保留 `Middlewares` 与 `Applications/lvgl_ui`。

### 换 RTOS

- 保留 LVGL、UI、LCD 接口。
- 替换 `Applications/runtime/app_tasks.c` 中线程创建、延时和 tick 来源。
- 确保所有 LVGL API 仍只在一个 GUI 线程中调用，或增加统一互斥保护。

## 8. 建议学习顺序

1. 先读 `Applications/runtime/app_tasks.c`，看线程怎样注册、启动和通信。
2. 再读 `lv_port_disp.c`，理解 LVGL 如何把一块像素区域交给 LCD。
3. 阅读 `ui_main_menu.c`，学习对象、样式、Grid 布局、状态和事件。
4. 阅读 `lv_port_indev.c`，理解物理按键如何变成 LVGL 焦点导航。
5. 阅读 `BSP/services/board_service.c`，再分别进入 `BSP/drivers/`，学习采集编排、软件 I2C、共享 SPI 和算法隔离。
6. 最后看 `st7789_fsmc.c`，学习原理图引脚、FSMC 地址映射和屏幕命令。

遇到黑屏时，按照“串口是否到 `[4/4]` → 背光 PF9 → 复位 PD3 → FSMC 引脚/时序 → LVGL flush 回调”的顺序排查，效率最高。PF8 在本板上是红外接收输入，不能用于 LCD 背光。

## 9. 调试方法

### 9.1 先用启动日志定位阶段

串口最后一条信息能快速缩小范围：

| 最后一条日志 | 优先检查 |
|---|---|
| 没有任何输出 | 供电、ST-LINK、USART1、115200 参数、程序是否运行 |
| 停在 `[1/4]` | FSMC 初始化、LCD 复位 PD3、FSMC 引脚和 HAL SRAM |
| 停在 `[2/4]` | LVGL 内存、显示对象和缓冲区 |
| 停在 `[3/4]` | PC0/PC1/PC4/PC5 配置、输入对象或焦点组 |
| 已到 `[4/4]` 但黑屏 | 背光 PF9、ST7789 初始化命令、flush 像素顺序 |

### 9.2 使用 ST-LINK 单步调试

可以在 STM32CubeIDE 中导入 CMake 工程，或创建 STM32 Cortex-M Debug 配置：

1. 调试文件选择 `build/codex-gcc/STM32F407_RTT.elf`。
2. Probe 选择 ST-LINK，接口选择 SWD，频率先用 4 MHz；不稳定时降到 1 MHz。
3. 初学时建议在 `gui_thread_entry()`、`st7789_init()`、`display_flush()` 和 `ui_main_menu_create()` 设置断点。
4. RTOS 启动后不要长时间停在关中断区域；单步导致调度时序变化时，应改用串口日志或条件断点。

### 9.3 HardFault 调试

程序进入 `HardFault_Handler()` 时不要立即复位：

- 查看 Call Stack，找到 HardFault 前最后一个业务函数。
- 查看 `SCB->CFSR`、`SCB->HFSR`、`SCB->BFAR` 和 `SCB->MMFAR`。
- `BFAR` 落在 `0x68000000` 附近通常意味着 FSMC 未初始化就访问 LCD，或地址映射错误。
- 发生在 LVGL 创建对象时，优先检查 GUI 线程栈和 LVGL 的 32 KiB 内存池。
- 使用 `arm-none-eabi-addr2line -e build/codex-gcc/STM32F407_RTT.elf <地址>` 可把故障地址还原到源代码行。

### 9.4 黑屏、花屏和颜色错误

- 背光亮但全黑：在 `display_flush()` 下断点，确认 LVGL 确实刷新；再检查窗口命令 `0x2A/0x2B/0x2C`。
- 背光不亮：测 PF9 是否为高电平，并执行 `backlight on` 后再次测量。
- 白屏：常见原因是 PD3 复位、PG10/NE3、PD4/NOE、PD5/NWE 或 FSMC 时序不对。
- 能进入 MSH 时先执行 `ui_status`；LCD ID 应为 `0x81B3`。ID 异常优先查 FSMC 总线，ID 正常但无背光优先查 PF9 和背光三极管。
- 图像错位：检查屏幕偏移和 `0x36` 扫描方向。
- 纯色画面且 CPU 暂停后仍频闪：先检查 RW007 是否已释放复位，以及 3.3 V 供电、屏幕排线和背光电路；本工程默认让 RW007 保持复位。
- 红蓝互换：检查 ST7789 的 RGB/BGR 位和 `LV_COLOR_FORMAT_RGB565`。
- 大面积花屏：先把 FSMC 写时序调慢，再检查 8 位总线 D0-D7 的焊接与引脚复用。

### 9.5 按键与焦点调试

四个键为低电平按下，驱动内置 25 ms 消抖。PC5/上键映射为上一项，PC1/下键映射为下一项，PC4/右键映射为确认，PC0/左键映射为返回。可输入 `key_status` 查看实时电平；按住某键时执行该命令，对应状态应为 `pressed`。

不要给主菜单卡片增加 `transform_scale` 按压样式。软件变换会建立离屏绘制层，在本板有限内存和 FSMC 刷新路径中曾导致确认键按下后系统停止响应；当前仅用背景色表达按下状态。

本板没有独立中心确认键，因此采用常见四键菜单映射。以后换成五向按键或旋转编码器，只需修改 `lv_port_indev.c`，UI 页面仍使用 LVGL 的 `PREV/NEXT/ENTER/ESC`，无需改动页面结构。

### 9.6 内存和性能

- 链接完成会打印 FLASH/RAM 使用率；接近 85% 时应留出升级余量。
- `gui_thread_stack` 当前为 6 KiB。复杂页面加入图片解码、动画或大量格式化文本后，应检查线程最大栈使用量。
- `board` 采集线程栈为 3 KiB，实测最大使用约 11%。
- 不要把全屏 RGB565 帧缓冲放入内部 SRAM；当前 24 行缓冲约 11.25 KiB。
- UI 卡顿时先统计 `display_flush()` 耗时，再考虑增大局部缓冲或用 DMA；不要盲目提高 GUI 线程优先级。

当前实测链接占用约 RAM 44.5%、Flash 51.4%；四页反复进入/返回后 RT-Thread 堆使用保持 5160 B，可用约 63 KiB。

## 10. 已知边界与后续开发

### 10.1 Storage 下一阶段

当前只做无损硬件检测，不会擦写 Flash 或格式化 SD 卡。加入官方组件时建议顺序为：

1. 加入 RT-Thread device、SPI 和 SDIO 驱动框架。
2. W25Q 使用 SFUD，分区使用 FAL，再按需要挂载 `/fal`。
3. SD 使用 SDIO block device、DFS 和 Elm-FAT，挂载 `/sdcard`。
4. 格式化属于破坏性操作，必须由明确命令触发，不能在启动时自动执行。

### 10.2 Network 下一阶段

当前 RW007 页面是真实硬件状态和复位控制，不是假联网状态。完整 Wi-Fi 需要加入官方 RW007 依赖：RT-Thread device、SPI/PIN、WLAN 管理层、netdev 和 lwIP。完成后应把扫描结果、SSID、RSSI、连接状态和 IPv4 写入 `board_service_snapshot_t`，UI 仍只读取快照。
