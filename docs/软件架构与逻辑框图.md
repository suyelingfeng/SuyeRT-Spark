# STM32F407 RT-Thread + LVGL 软件架构与逻辑框图

本文用于二次开发、学习和故障定位。它说明工程各层的职责、线程如何启动、
数据如何在线程之间传递，以及增加新驱动或新 UI 功能时应修改哪些文件。

## 1. 总体分层

```mermaid
flowchart TB
    USER["用户：实体按键 / ST-LINK 串口"]

    subgraph APP["Applications 应用层"]
        UI["lvgl_ui<br/>页面、动画、导航、业务事件"]
        PORT["lvgl_port<br/>显示与按键适配"]
        SHELL["shell_commands.c<br/>MSH 调试命令"]
        TASKS["runtime/app_tasks.c<br/>线程注册、启动与线程间通信"]
    end

    subgraph SERVICE["BSP/services 服务层"]
        BOARD["board_service.c<br/>20 ms / 500 ms 调度与数据编排"]
    end

    subgraph ALGORITHM["BSP/algorithms 算法层"]
        FUSION["sensor_fusion.c<br/>一维 Kalman / Mahony / 四元数 / 零偏跟踪"]
    end

    subgraph DRIVER["BSP/drivers 驱动层"]
        BUS["bus<br/>软件 I²C / SPI2"]
        SENSOR["sensors<br/>AHT21 / AP3216C / ICM20608"]
        STORAGE["storage<br/>W25Q / SD Detect"]
        WLAN["wireless<br/>RW007 复位与状态"]
        LCD["lcd<br/>ST7789 + FSMC"]
    end

    subgraph PLATFORM["Core / HAL / RT-Thread 平台层"]
        RTOS["RT-Thread 5.2.2"]
        HAL["STM32 HAL / CMSIS / CubeMX"]
        HW["STM32F407ZGT6 与板载外设"]
    end

    USER --> UI
    USER --> SHELL
    UI --> TASKS
    SHELL --> TASKS
    TASKS --> BOARD
    BOARD --> SENSOR
    BOARD --> STORAGE
    BOARD --> WLAN
    BOARD --> FUSION
    SENSOR --> BUS
    STORAGE --> BUS
    PORT --> LCD
    TASKS --> RTOS
    BUS --> HAL
    WLAN --> HAL
    LCD --> HAL
    RTOS --> HAL
    HAL --> HW
```

分层原则：

- UI 不读写 GPIO、I²C 或 SPI，只读取状态快照、提交异步请求。
- `app_tasks.c` 是线程注册、线程启动、共享快照和请求标志的唯一管理点。
- `board_service.c` 组合驱动和算法，但不创建 RT-Thread 线程。
- 每个驱动只处理自己的引脚、寄存器、时序和物理量换算。
- 算法层不访问 HAL、RT-Thread、LVGL，方便移植和离线测试。

## 3. 系统启动逻辑框图

```mermaid
flowchart TD
    RESET["上电或复位"] --> MAIN["main.c"]
    MAIN --> HALINIT["HAL_Init"]
    HALINIT --> CLOCK["SystemClock_Config<br/>HSE 8 MHz -> 168 MHz"]
    CLOCK --> CUBE["CubeMX GPIO / FSMC / USART1 初始化"]
    CUBE --> RTT["rtthread_startup"]
    RTT --> KERNEL["堆、时钟、调度器初始化"]
    KERNEL --> APPINIT["rt_application_init"]
    APPINIT --> TASKSTART["app_tasks_start"]
    TASKSTART --> BOARDTHREAD["注册并启动 board 线程<br/>优先级 19 / 栈 3072 B"]
    BOARDTHREAD --> GUITHREAD["注册并启动 lvgl 线程<br/>优先级 18 / 栈 6144 B"]
    GUITHREAD --> FINSH["finsh_system_init<br/>启动 tshell / suye 提示符"]
    FINSH --> SCHED["启动 RT-Thread 调度器"]
    SCHED --> RUN["三个应用线程并发运行"]
```

注意：RT-Thread 的优先级数字越小，优先级越高。GUI 使用 18，board 使用 19，
FinSH 默认约为 20，使短时间 LCD 刷新优先完成。线程循环都主动休眠，不会忙等占满 CPU。

## 4. 线程与通信逻辑框图

```mermaid
flowchart LR
    subgraph BOARD_THREAD["board 线程，每 20 ms"]
        TAKE["原子取走请求"] --> PROCESS["board_service_process"]
        PROCESS --> LOCAL["更新局部 current 快照"]
        LOCAL --> PUBLISH["短暂关中断，整体发布 shared_snapshot"]
    end

    subgraph GUI_THREAD["lvgl 线程，每 5 ms"]
        NAV["处理延迟页面切换"] --> TIMER["lv_timer_handler"]
        TIMER --> READUI["功能页每约 500 ms 复制快照"]
    end

    subgraph SHELL_THREAD["tshell 线程"]
        CMD["解析 suye> 命令"] --> READCMD["状态命令复制快照"]
    end

    BUTTON["UI 操作：刷新 / 归零 / RW007"] --> REQUESTS["pending_requests"]
    CMDREQ["MSH 操作命令"] --> REQUESTS
    REQUESTS --> TAKE
    PUBLISH --> SNAPSHOT["shared_snapshot"]
    SNAPSHOT --> READUI
    SNAPSHOT --> READCMD
    CMDUI["MSH 重绘命令"] --> REDRAW["ui_redraw_requested"]
    REDRAW --> NAV
```

跨线程规则：

1. board 线程始终先更新局部 `current`，不直接逐字段修改共享快照。
2. 发布和复制快照只在很短的关中断区内完成，不包含 I²C、SPI 或浮点计算。
3. UI 和 MSH 只置请求标志，不等待耗时外设操作完成。
4. 所有 `lv_*` API 只能由 lvgl 线程调用。
5. 姿态校准完成前收到的“设为正方向”请求会保留，校准完成后自动执行。

公共通信接口位于 `Applications/runtime/app_tasks.h`：

| 接口 | 用途 | 调用者 |
|---|---|---|
| `app_tasks_start()` | 创建 board、lvgl、tshell | `app_init.c` |
| `app_tasks_get_board_snapshot()` | 原子复制板载状态 | UI、MSH |
| `app_tasks_request_board_refresh()` | 请求慢速设备立即更新 | UI、MSH |
| `app_tasks_request_rw007_reset()` | 请求复位并启动 RW007 | UI、MSH |
| `app_tasks_request_attitude_zero()` | 请求把当前方向设为正方向 | UI、MSH |
| `app_tasks_request_ui_redraw()` | 请求 GUI 下一轮整页重绘 | MSH |

## 5. 板载采集与算法逻辑框图

```mermaid
flowchart TD
    LOOP["board 线程一轮"] --> ENV["轮询 AHT21 转换是否达到 85 ms"]
    ENV --> IMU["读取 ICM20608<br/>加速度 / 陀螺 / 温度"]
    IMU --> READY{"姿态算法已校准？"}
    READY -- "否" --> CAL["连续静止 300 帧 / 约 6 秒<br/>计算陀螺零偏、温度和开机方向"]
    READY -- "是" --> MAHONY["Mahony 四元数更新<br/>重力校正 roll/pitch"]
    MAHONY --> ZUPT["静止检测与在线零偏跟踪"]
    ZUPT --> EULER["相对四元数 -> 欧拉角"]
    EULER --> KANGLE["三个显示角一维 Kalman"]
    CAL --> SLOW
    KANGLE --> SLOW{"到 500 ms 或收到刷新请求？"}
    SLOW -- "否" --> RW["读取 RW007 INT/BUSY"]
    SLOW -- "是" --> ALS["读取 AP3216C 环境光"]
    ALS --> FLASH["读取 W25Q JEDEC / SD Detect"]
    FLASH --> AHTSTART["启动下一次 AHT21 非阻塞转换"]
    AHTSTART --> RW
    RW --> RWREQ{"收到 RW007 启动请求？"}
    RWREQ -- "是" --> RST["RST 低 100 ms<br/>释放并等待 BUSY/INT"]
    RWREQ -- "否" --> PUB["sequence++ 并发布快照"]
    RST --> PUB
```

采样周期：

| 路径 | 周期 | 说明 |
|---|---:|---|
| ICM20608 与姿态融合 | 20 ms，约 50 Hz | 使用实际 RT-Thread tick 计算 `dt` |
| AHT21 转换轮询 | 每轮检查 | 转换需约 85 ms，但不阻塞线程等待 |
| AP3216C、W25Q、SD | 500 ms | 也可由 UI/MSH 请求立即刷新 |
| UI 状态文本 | 约 500 ms | 只读快照，不访问硬件 |
| LVGL 主循环 | 5 ms | 按键、动画、重绘和 flush |

## 6. 姿态算法和零漂处理

```mermaid
flowchart LR
    RAW["ICM20608 原始数据"] --> SCALE["±2 g / ±250 dps 换算"]
    SCALE --> BOOTCAL["开机静止零偏校准"]
    BOOTCAL --> QUAT["Mahony 四元数积分"]
    ACC["加速度重力方向"] --> QUAT
    QUAT --> STILL["静止判断"]
    STILL --> BIAS["在线陀螺零偏跟踪"]
    BIAS --> QUAT
    BIAS --> TMODEL["温差达到 0.5°C<br/>学习三轴 dps/°C 系数"]
    TMODEL --> TCOMP["温度前馈补偿"]
    TCOMP --> QUAT
    QUAT --> REL["相对开机或手动零方向"]
    REL --> ANGLE["roll / pitch / yaw"]
    ANGLE --> KALMAN["一维 Kalman 平滑显示"]
```

- ICM20608 没有磁力计，yaw 只有相对方向，没有绝对地磁参考。
- 重力可以长期约束 roll/pitch，但不能从物理上消除 yaw 长期漂移。
- 开机校准和按下 SET ZERO 时应保持开发板静止。
- 开机使用 300 帧平均；在线零偏跟踪只在加速度接近 1 g、角速度很小并持续静止时启用。
- UI 与串口只显示 corrected 补偿值；原始角速度仅在算法内部参与计算，不进入公共快照。
- 需要绝对航向时，应增加磁力计或外部航向参考并升级到九轴融合。

## 7. UI 和实体按键逻辑框图

```mermaid
stateDiagram-v2
    [*] --> Boot
    Boot --> Home: 开机动画结束
    Home --> Sensors: RIGHT 确认
    Home --> TempRH: RIGHT 确认
    Home --> Attitude: RIGHT 确认
    Home --> Storage: RIGHT 确认
    Home --> Network: RIGHT 确认
    Home --> System: RIGHT 确认
    Sensors --> Home: LEFT 返回
    TempRH --> Home: LEFT 返回
    Attitude --> Home: LEFT 返回
    Storage --> Home: LEFT 返回
    Network --> Home: LEFT 返回
    System --> Home: LEFT 返回
```

按键映射：

| 实体键 | LVGL 键值 | 功能 |
|---|---|---|
| UP | `LV_KEY_PREV` | 上一个可聚焦控件 |
| DOWN | `LV_KEY_NEXT` | 下一个可聚焦控件 |
| RIGHT | `LV_KEY_ENTER` | 确认、进入页面、执行按钮 |
| LEFT | `LV_KEY_ESC` | 返回主页 |

页面切换不在按键回调中立即删除当前 screen。回调只提交导航请求，
`ui_navigation_process()` 在下一轮 GUI 循环中创建新页面、切屏并删除旧页面，
避免确认/返回过程中访问已经释放的 LVGL 对象。

## 8. 防频闪相关逻辑

当前实机稳定策略必须在二次开发时保留：

- ST7789 使用局部刷新，不周期性执行整屏清空或重新初始化。
- AP3216C 只启用 ALS，关闭会产生脉冲电流的 PS/IR 发射。
- RW007 开机保持 `RST=low`，只在 Network 页面或 MSH 命令明确请求时启动。
- 不在 GUI 线程执行 AHT21 的 85 ms 转换等待、RW007 复位等待或 SPI 探测。
- 如果 RW007 启动后仍频闪，应优先检查 3.3 V 电源、地线和模块附近去耦。

## 9. 增加新外设的标准步骤

以增加一个新的 I²C 传感器为例：

1. 在 `BSP/drivers/sensors/` 新建 `new_sensor.c/.h`。
2. 驱动头文件只公开初始化、读取以及必要的数据结构。
3. 驱动使用 `soft_i2c_*`，不要调用 LVGL，也不要创建线程。
4. 在 `board_service_snapshot_t` 增加 UI 所需的稳定数据字段。
5. 在 `board_service_init()` 初始化设备。
6. 在 `board_service_process()` 的高频或慢速路径调用驱动。
7. 在 `app_tasks.h` 增加请求接口；请求标志仍只放在 `app_tasks.c`。
8. UI 通过快照显示结果，按键回调只提交请求。
9. 将新 `.c` 加入 `CMakeLists.txt`，完整编译后再烧录。

禁止把以下内容混在新驱动中：

- `rt_thread_init()` 或 `rt_thread_startup()`；
- `lv_label_set_text()` 等 LVGL 调用；
- 页面编号、焦点组或串口命令解析；
- 与该器件无关的其他传感器寄存器。

## 10. 移植时替换范围

| 需求 | 主要修改 | 尽量保持不变 |
|---|---|---|
| 更换同类传感器 | 对应 `BSP/drivers/sensors/` 和服务编排 | UI、线程通信、其他驱动 |
| 更换 LCD | `BSP/lcd/`、必要时 `lv_port_disp.c` | 页面业务、传感器服务 |
| 换成触摸或编码器 | `lv_port_indev.c` | 页面和导航接口 |
| 更换 STM32 板卡 | CubeMX/Core、总线和 GPIO 驱动 | 算法、快照接口、UI |
| 更换 RTOS | `app_tasks.c`、tick/临界区接口 | 驱动寄存器逻辑、算法、UI结构 |
| 接入 RT-Thread Sensor/FAL/WLAN | 驱动和 `board_service.c` | `app_tasks_*` 和快照消费者 |

移植的核心是保持两个边界稳定：

1. UI/MSH 面向 `app_tasks_*`，不面向具体硬件。
2. `board_service_snapshot_t` 作为显示与诊断的数据协议尽量保持兼容。

## 11. 调试定位顺序

```mermaid
flowchart TD
    START["故障出现"] --> UART{"USART1 115200 有启动日志？"}
    UART -- "否" --> CLOCKUART["检查供电、时钟、ST-LINK VCP、USART1"]
    UART -- "是" --> STAGE{"日志停在哪个 [1/4]~[4/4] 阶段？"}
    STAGE --> LCDCHK["[1/4]：FSMC、ST7789、PF9 背光、PD3 复位"]
    STAGE --> LVCHK["[2/4]：LVGL 初始化和显示注册"]
    STAGE --> KEYCHK["[3/4]：PC0/PC1/PC4/PC5 与输入组"]
    STAGE --> RUNCHK["[4/4] 后：ps / free / ui_status / key_status"]
    RUNCHK --> BOARDCHK["sensor_status / environment_status / attitude_status"]
    BOARDCHK --> POWER["只在启动 RW007 后频闪：检查 3.3 V 电源与去耦"]
```

建议首先阅读 `Applications/runtime/app_tasks.c`，它能看到整个系统的线程和数据流；
随后阅读 `BSP/services/board_service.c`，再进入需要修改的具体驱动。这样学习和排错
都不必从 500 多个 RT-Thread/LVGL 源文件中盲目查找。
